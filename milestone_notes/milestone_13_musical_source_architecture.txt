POST-TRIAL MULTI-PLOT REMEDIATION — 2026-08-15

- User musical testing accepted the M13 generator upgrades but reported that live Multi-Plot additions still popped and that co-located endpoints became visually hidden on a populated grid.
- Root cause of the ineffective longer fade: topology insertion scheduled the intended 60 ms zero-to-live ramp, then canonical spatial-state synchronization immediately reapplied the already-current Live Trim value. That redundant update cancelled the insertion automation and replaced it with the ordinary 20 ms control ramp.
- `setLiveTrim` is now idempotent. Reapplying an unchanged canonical value performs no AudioParam scheduling, so the live branch's 60 ms insertion fade survives intact. A focused runtime test proves the final scheduled ramp time remains unchanged after spatial synchronization.
- This is a mechanical scheduling correction, not another arbitrary fade extension. The source oscillator and source envelope remain uninterrupted and no additional source is created.
- Co-located plots now receive deterministic, centred visual offsets in a compact square fan. Their audio coordinates remain identical; the offset is presentation-only.
- Every stacked endpoint exposes `data-stack-index` and `data-stack-size`, its accessible label states its stack position, and the top plot displays the total stack count. Selection raises the addressed endpoint without hiding the remaining stack structure.
- Focused browser verification proves two plots on `(0,0)` occupy distinct visible centres while retaining the same canonical routing coordinate.
- A second user trial confirmed the two-plot fan but found corner-based access unsuitable from three occupants upward, and confirmed that the pop remained after the insertion-ramp correction.
- Live insertion now coordinates the complete family transition: every existing programmed-gain branch uses the same 60 ms interval as the new endpoint instead of retaining the generic 20 ms family-rebalance ramp. This addresses the remaining parallel automation path without restarting the oscillator or manufacturing another source.
- At three or more occupants, the grid exposes one Plot Point Folder trigger rather than requiring clicks on partially visible endpoints. The Plotter folder lists every occupant in explicit FRONT/LAYER/BACK order with select, bring-forward, and send-back controls.
- Layer order is canonical spatial presentation state. Reordering a folder does not alter sourceId, coordinate, pan, pitch, generator, Live Trim, mute, or audio-node ownership.
- Recording inspection was blocked by a malformed/unfinalized QuickTime media index, but the runtime audit exposed a separate gain-law error: every Multi-Plot carries the same phase-coherent oscillator signal while family amplitude used `1 / sqrt(N)`, which is appropriate only for uncorrelated sources and raises the coherent summed level as endpoints are added.
- Family amplitude normalization is now `1 / N`. Existing branches ramp down while the zero-gain new branch ramps up over the same 60 ms window, preserving the family's summed programmed gain instead of introducing a tone-relative level transient.
- A regression adds one through five live endpoints and proves that all branches retain one oscillator and their summed programmed gain remains constant at every final topology.
- User listening confirmed that coherent normalization softened but did not eliminate the insertion transient, separating the level-jump component from the remaining live graph-mutation component.
- Live insertion now holds the new branch at zero and holds existing family gain unchanged for 10 ms before the coordinated 60 ms crossfade begins. This gives the Web Audio renderer several silent processing quanta to commit the connected branch before it contributes to output.
- The insertion regression proves the explicit hold event and synchronized fade completion time on both the new branch and the existing family.
- The original 65.4-second iPad recording decoded successfully. Its spectrogram showed the 84 Hz Triangle harmonics continuing through the Multi-Plot actions while prominent narrow broadband impulses extended to approximately 20 kHz, consistent with the nearby microphone capturing the physical input mechanism at the same instant.
- The user explicitly accepted delayed clone delivery in exchange for live-recording cleanliness. The earlier 10 ms hold/60 ms linear transition is therefore superseded by a one-second fully silent staging interval and a coordinated 250 ms smoothstep curve with zero slope at both endpoints.
- The existing family does not rebalance during the one-second staging interval. New and existing branches then use the same shaped curve, preserving coherent `1 / N` summed gain throughout delivery.
- Rapid user additions revealed that independently scheduled delayed curves could overlap: an earlier endpoint could begin entering after a later click had postponed the existing-family rebalance, temporarily doubling amplitude before normalization caught up.
- Insertion staging is now a debounced transaction owned by the complete source family. Each rapid addition resets the family's one-second timer; every queued endpoint remains at zero programmed/trim output and delivered endpoints remain unchanged until no further addition arrives for a full second.
- The transaction assigns silent pending branches their final programmed gain, then applies one shared 250 ms smoothstep to delivered-family normalization and every pending Live Trim. No endpoint retains an autonomous delayed curve.
- A focused rapid-addition regression queues two endpoints, proves the first timer is cancelled, confirms both branches remain silent before delivery, and samples all 65 curve points to prove summed family gain remains equal to the original gain without temporary overshoot.
- User testing found that the 3+ Plot Point Folder trigger prevented dragging the occupied coordinate. The folder trigger now acts as a cluster drag handle and previews every member's panner together before committing one atomic `move-plot-stack` spatial action.
- Cluster movement preserves every endpoint's sourceId, pitch/generator ownership, Live Trim, mute, analyser, plot number, and layer order. It is an operation rather than a permanent grouping contract.
- Folder guidance makes the escape paths explicit: select one member, choose another grid coordinate, and Plot route to move it independently; REMOVE still destroys only the selected Multi-Plot endpoint.
- Model and production-browser coverage move a three-endpoint folder, route one member out so the residual cluster collapses to two, and delete another member without altering the survivor or source oscillator.

Double-click any member in the Plot Point Folder to pull that live endpoint into an exposed, dashed-outline drag target. The selected member can also be pulled by double-clicking the grid folder marker; if no member in that folder is selected, the front endpoint is used.

The endpoint remains live at its original coordinate until normal dragging commits a new coordinate, while the remaining occupants continue to render as their own cluster.
