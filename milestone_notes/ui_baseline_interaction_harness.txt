RFE MILESTONE NOTE

Component:
UI Baseline & Interaction Harness

Status:
APPROVED — 2026-08-10

WHAT IT IS
The approved RFE interface is now a state-driven interaction harness. Thread modules are independent application instances with canonical parameters, positions, selection, ports and grouping accents. Thread connections are committed routing objects rather than decorative lines. The Inspector, module cards and Diagnostics are views onto the same application state.

WHY IT EXISTS
This layer proves the application shell can safely support later audio and simulation systems without coupling the approved UI to unfinished engines. It provides reliable interaction, routing, timing, cleanup and workload evidence before sound generation is introduced.

IMPLEMENTED DECISIONS
- One reducer-owned canonical application state governs modules, parameters, selection, positions, Threads, controls, diagnostics and test-session timing.
- Inspector edits update the selected module instance directly; switching instances preserves independent values.
- Modules support pointer movement. Committed Thread geometry follows endpoints continuously.
- The workspace edit bar adds enabled module types, selects all modules, duplicates or deletes the current selection, and clears the complete workstation with confirmation.
- Shift-, Command- or Control-click builds a multi-module selection. Dragging any selected module moves the batch while preserving relative positions.
- Module names are editable in the Inspector. Batch duplication copies independent module state and only the committed Threads whose two endpoints are both inside the batch; deletion removes every attached Thread without leaving orphans.
- Inspector sections use native collapsible groups, keeping dense controls available while allowing a cleaner minimized view.
- Workspace width can extend from its fluid 100% baseline to 150% and 200% in one-click steps. Added regions are visibly sectioned, horizontally scrollable, measured in pixels in the edit bar, and capped at 100% extra space.
- The single workspace-width control changes from Extend to Retract at maximum width and steps safely through 100%, 150% and 200% in both directions.
- Thread endpoint geometry follows the effective module dimensions in Studio, Compact and narrow responsive layouts, preventing visible gaps at ports.
- Output-to-input routing supports deliberate creation, validation, selection and Delete/Backspace or Inspector removal.
- Future modules remain selectable for inspection but reject controls and connections.
- Active sliders, selectors, segmented controls, toggles, tabs, view controls, themes, layouts, presets and session actions are wired to state.
- Diagnostics report actual active module count, committed Thread count, selected object, state updates and elapsed session time.
- Elapsed time is derived from performance.now() and is therefore monotonic rather than frame- or callback-counted.
- RFE_32x32_Benchmark remains a controlled, repeatable workload fixture alongside the new module lifecycle tools.
- The 15-minute live benchmark completed at 15:24 with 32 modules, 32 committed Threads, one selected module, 764 state updates, zero recorded consistency errors and no browser console warnings/errors.
- A focused Playwright journey challenges timer behavior, independent module edits, movement, live Thread geometry, connection creation/deletion, active controls, future-state restrictions and Diagnostics coherence.
- An axe-core browser smoke check blocks serious or critical accessibility violations. GitHub Actions runs this alongside the build, typecheck and lint checks.
- `npm run test:stress-ui` verifies the 32-module / 32-Thread fixture and prints the concise manual soak procedure; the long soak intentionally remains outside CI.

OUTSTANDING
- Focus is not present in the approved repository and was not invented for this milestone.
- Free window movement, resizing, minimising and closing are not implemented; their visible controls are explicitly disabled and labelled unavailable.

DEPENDENCIES / NOTES
- No audio engine, scheduler, sample playback, audio clock or particle engine is present.
- The UI Workshop remains development-only and separate from canonical application interaction state.
- The benchmark preset is intended for repeatable UI workload testing, not as an end-user project preset.
- The quality gate requires Node.js 22, pnpm, Chromium installed by Playwright, and standard GitHub-hosted runners. No secrets or external services are required.
