3. AUDIO OWNERSHIP MODEL

Authoritative runtime:
- `app/audio-runtime.ts` exports the module-level `applicationAudioRuntime` singleton.
- Audio lifecycle correctness does not depend on a React component remaining mounted.

Application-level ownership:
- One lazily created AudioContext/runtime.
- One shared master gain connected once to the AudioContext destination.
- Shared lifecycle coordination and explicit application shutdown.
- Master/runtime diagnostic counters and runtime error state.

Channel-level ownership:
- Oscillator/source.
- Short source envelope.
- Channel gain.
- Channel analyser.
- Channel parameters, status and scoped cleanup.

Graph:
`CHANNEL SOURCE -> SOURCE ENVELOPE -> CHANNEL GAIN -> CHANNEL ANALYSER -> SHARED MASTER -> DESTINATION`

Lifecycle contracts:
- Changing frequency or level never recreates the master, channel graph or oscillator.
- Starting an already-active channel is idempotent.
- Stop disposes only the current oscillator/envelope and leaves reusable channel processing plus shared output intact.
- Restart creates exactly one new channel source.
- Channel disposal never closes the AudioContext or replaces/disconnects shared output.
- Only explicit application shutdown may close shared infrastructure.
- UI observer remount/navigation does not reconstruct the master graph.
- Initialisation errors are visible and retryable without crashing unrelated workspaces.

This isolation model is the required inheritance boundary for future CH 02, CH 03 and later concurrent instances. Additional audible channels are not implemented yet.

6. IMPORTANT IMPLEMENTATION DECISIONS

- Application audio infrastructure and channel audio instances have separate ownership. Do not move AudioContext creation into a transient component.
- Do not close/reset shared audio resources during channel Stop, parameter changes, channel disposal or UI remount.
- Future audible channels must receive independent source/gain/analyser ownership and connect into the existing shared master.
- Audio is local/browser-native. No remote processing, cloud audio service or server-side audio dependency exists.
- Conservative gain staging is intentional: channel maximum 0.2, shared master 0.8 and default level 20%.
- There is no limiter/mastering chain. Start manual listening at conservative device volume.
- Workspace navigation intentionally permits CH 01 to continue. Changing this policy requires an explicit product decision and lifecycle tests.
- Spatial routing and audio generation remain separate. Coordinates are retained data but do not pan or process sound.
- Dynamic channel numbering is based on active channel state, not a permanent lifetime counter. Gaps below the current maximum are not reused while channels remain.
- Channel list scrolling is internal to Inputs & Channels. Do not allow flex/grid shrink to clip fixture content or controls.
- AppState remains the source of truth for application interaction. Audio runtime state is engine state and must not be duplicated into reducer/UI state.
- Visual configuration remains separate from both AppState and audio-engine state.
- Existing cleanup invariants, stable identity, spatial ownership and navigation contracts remain in force.

7. DO-NOT-BREAK CONTRACTS

- One active channel source must never recreate or replace shared output.
- Stop must silence/dispose the channel source; Restart must return exactly one source.
- Channel disposal must remain scoped and must never close the application AudioContext.
- Frequency/level updates must target the current source/channel graph without parallel oscillator creation.
- Monitor must reflect actual active state, frequency and level; the waveform must use analyser data rather than decorative animation.
- No autoplay. Audio initialization/resume must follow an explicit user gesture.
- Preserve accessible Start/Stop, frequency slider, exact frequency buttons, level control and text state.
- Preserve active-state channel numbering: empty -> 01; otherwise max(active)+1; never duplicate an active ID.
- Preserve full-height, independently scrollable dynamic channel rows and reachable remove controls at large populations.
- Removing a channel must remove only its own terminal/spatial/audio resources and retain peers.
- Preserve reducer ownership, module/Thread distinction, connection validation and orphan cleanup.
- Preserve canonical spatial coordinates and Sound Desk/Visualiser shared routing truth.
- Do not add multi-channel audio, panning, spatial audio, distribution, effects, recording, file playback or simulation without an explicit milestone brief.
- Maintain TypeScript, ESLint, production build, model/browser regression and axe gates.

8. KNOWN LIMITATIONS / DEFERRED WORK

- Only CH 01 is audible. Additional dynamic channels are routing/test-bed structures only.
- Audible behavior depends on browser/device output. Automated tests prove lifecycle and analyser behavior, not human-perceived sound quality.
- Short ramps reduce likely clicks but device-specific clicks/pops remain a listening concern for future work.
- No stereo panning, X/Y audio mapping, HRTF, binaural/surround processing or distribution engine.
- No live input, recording, sample/file playback, loops, effects, EQ, compression or mastering protection.
- No particle/field simulation or audio/visual gating.
- Persistence remains browser-local; there is no durable project database/collaboration contract.
- Free window management, product Focus/Favourites and deeper workflows remain deferred.
- Audio diagnostics are exposed for engineering validation but are intentionally not a full user-facing telemetry panel.
