The application is a local, editable RFE research-interface prototype with three directionally ordered workspaces: Threads, Sound Desk and Visualiser. Threads owns five stable channel outputs and their actual terminal connectivity. Sound Desk derives incoming availability, authors spatial assignments through a Channel Rail and Plotter, and retains the canonical 5 × 5 grid. Visualiser observes the same routing state. There is no audio, mixer, distribution, particle, field, or simulation engine.

Repository reconciliation is complete on the review branch. Merge that reviewed branch before treating the remote default branch as the Milestone 05 baseline.

5. IMPORTANT IMPLEMENTATION DECISIONS

- AppState in `interaction-state.ts` is the single source of truth for application interaction. Do not reintroduce parallel component-local copies of module, connection, selection, parameter, lifecycle, workspace-width, or session state.
- Visual configuration is intentionally separate from AppState. UI Workshop changes must not mutate routing, module logic, Diagnostics truth, session state, or future engine state.
- Modules and Threads are distinct concepts: module boxes are ModuleInstance objects; routing lines are ThreadConnection objects. Preserve this terminology in state and user-facing actions.
- A multi-module Selection retains a primary `id` and an optional ordered `ids` list for backward-compatible single-selection behaviour. Use `getSelectedModuleIds` rather than reading `selection.ids` directly.
- Batch duplication copies only internal selected-to-selected Threads. It must not silently create connections from duplicated modules back to unselected originals.
- Deleting modules and restored-state sanitation must remove orphaned Threads. Connection endpoint integrity is a reducer/storage contract.
- Future modules remain inspectable but disabled. They are architectural placeholders, not partially functional modules.
- Elapsed session time is calculated from monotonic timestamps rather than UI intervals or update counts.
- The canvas stage is percentage-positioned and may be 100%, 150%, or 200% of the visible canvas width. The width direction is canonical state so one control can complete both extend and retract sequences.
- Compact mode uses a 90% CSS transform above the narrow breakpoint. ThreadLayer must receive the matching effective node width and height; the narrow responsive media query removes that transform. Changing this without updating geometry will recreate visible gaps at Thread starts/ends.
- Threads is conditionally mounted by workspace navigation. Its ResizeObserver must follow `activeWorkspace`, measure the newly mounted canvas immediately, and ignore zero-size stale measurements; otherwise Thread endpoints collapse to the left edge after returning from another workspace.
- The approved grouping highlight baseline is an inset bar: 1px from top, 3px from sides, 1.5px thick. Full-border remains an enabled alternate style.
- The configuration revision deliberately invalidates older incompatible browser-local visual payloads. Do not change the revision or storage keys casually.
- Native dependency build approval is explicit and narrow in `pnpm-workspace.yaml`: esbuild, sharp, and workerd only. Do not replace it with broad dependency-script permission.
- The long 32/32 soak remains manual; CI intentionally runs the deterministic model, render, browser, and accessibility gates.
- The spatial coordinate definition in `spatial-routing.ts` is canonical. Do not create separate Sound Desk and Visualiser point lists or invert the documented Cartesian screen orientation.
- Spatial assignments belong to channel records. `getChannelsAtCoordinate` intentionally returns an array; do not replace it with a single-value coordinate occupancy map, because future stacked routing may place multiple channels at one point.
- Sound Desk availability is derived from Threads-owned terminal data. Do not add a manually synchronized rail-status list.
- Sound Desk selection/proposal state is transient UI state; committed coordinate assignments remain in the spatial reducer.
- When terminal completeness is lost, the shell removes any now-invalid spatial assignment. Unplot remains a Sound Desk-only operation and never mutates Threads.
- Visualiser inspection is an observer of routing state, not an independent mutable copy.
